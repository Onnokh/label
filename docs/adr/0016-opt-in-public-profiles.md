# Opt-In Public Profiles with Handles

Sleevy will let an Account publish a **Public Profile** at `/u/{handle}`, showing a **Handle**, a **Reading Activity** grid of daily save counts, and a paged list of that Account's Saved Items. A Handle is claimed when the profile is first turned on and lives in a dedicated one-to-one profile record rather than on the auth user, because a Handle is a product identifier and not a credential; the record survives turning **Profile Visibility** back off so a private Account keeps its Handle reserved, and only account deletion releases it. Handles are 3–30 characters of `a–z`, `0–9`, `-`, and `_`, are stored lowercase, exclude a reserved list that protects existing and future root paths, and are unique through an index on `lower(handle)`, following the convention already used for Folder names. Publishing is deliberately inverted: once Profile Visibility is public, every Saved Item is public unless the item itself is marked private, unless its Folder is marked private, or unless it was created less than one hour ago, and that rule is resolved in SQL when the public list is read rather than denormalized onto rows. The one-hour cutoff lives in the query because the codebase reads the wall clock directly and has no injected clock to control, so Postgres owns the boundary and the integration suite can prove it. A per-Folder publish flag and a separate publishable Collection object were both considered as the unit of publishing and rejected for the same two reasons: each adds an audience decision to every Folder a user creates, and each overloads **Folder**, which exists to help its owner find things later, with a second unrelated meaning. Sleevy accepts the consequence of the inversion — turning a profile on republishes an entire existing library at once with no review screen, and every later **One-Tap Capture** from clients that never prompt publishes automatically — because that is the only version of the feature people use; the opt-in confirmation copy therefore carries the whole safety burden, backed by the one-hour delay and a one-action private marker on Web Companion rows. Identity on the page is the Handle alone: no display name, no bio, and no avatar, so Sleevy never republishes a Google profile image or makes every visitor request one.

**Reading Activity** counts saves only, never reads, and counts first captures only, bucketed by Saved Item creation time in UTC across a rolling 52 weeks. Last-saved time is deliberately not used, because a **Duplicate Save** would silently rewrite the past every time an old Link returns through **Renewed Intent**, and per-viewer timezone bucketing is deliberately not used because it would give every visitor a different response and destroy shared caching. The grid counts private Saved Items and items inside private Folders as counts only, with no switch to hide it, on the reasoning that a count is not a URL and a graph restricted to published items would be too empty to be worth building. Public reads are served by a new unauthenticated REST group of three endpoints — profile, activity, and paged items — that returns 404 for an unknown Handle and for a private Account alike, so the API never discloses that a Handle exists. Those endpoints return a separate public Saved Item representation defined as an allow-list rather than reusing the existing Saved Item DTO, so that Folder name, Source name, Capture Channel, read state, and the internal Saved Item identifier stay private and no future field leaks by default. Because these routes carry no API Key, the **API Key Rate Limit** cannot apply and per-IP limiting is added, keyed on the Cloudflare connecting-IP header, which is the only trustworthy client address behind the production proxy chain. Search indexability is decided in the API — an Account at least 7 days old with at least 5 public items — and returned as a boolean so the web layer renders a robots directive from a value and owns no part of the rule, which keeps that decision inside an existing tested seam and leaves no reason to introduce test infrastructure for the web app. Public pages use real paged URLs rather than infinite scroll, which a crawler cannot reach, carry `rel="ugc nofollow"` on every user-published outbound link so Sleevy is not worth targeting for link spam, and cache for five minutes, which combined with the one-hour rule makes a save visible 60–65 minutes after capture. Signed-in visitors get a Save button attached after the cached HTML lands so the served markup never varies per viewer, and those saves record a new `public-profile` **Capture Channel**; the existing iOS client decodes Capture Channel as a plain string, so adding the value needs no client release ordering.
